Helios link debug

checks of the links between the GPUs and the switch trays
Live

Start here

This tool checks every link between the GPUs (in the compute trays) and the switch trays of a rack, tells you which links are not working and why, and what to do about it. It only reads - nothing on the rack is changed - except the one tool marked "disruptive" (Expert mode).

    Scale-up topology (g02-g17 full rack)

    What is this?
    What
    How every GPU port of the g02-g17 full rack is cabled to a switch port: 18 compute trays x 4 GPUs x 36 ports over 6 switch trays, and which switch chip serves which plane.
    When
    To understand why a problem on one switch chip or one GPU port number affects many GPUs, or to find where a port is cabled.
    How long
    Instant.
    Safe?
    Yes - a reference page; nothing is read from the rack. For a mini rack (MR2, MR3) use the Rack map after a check.

    Diagnose one link

    What is this?
    What
    Everything about ONE link: both ends, the switch chip's signal, what is around it, and a 24-hour timeline of what happened to it.
    When
    When one link is reported bad, or someone asks about a specific port.
    How long
    About 30-60 seconds.
    Safe?
    Yes - it only reads.

    Paste whatever you have for the link; only its switch tray and its compute tray are read. Read-only.

    Start from either end: a compute tray / GPU, or a switch tray / port - the other end follows.

    Watch links

    What is this?
    What
    Reads chosen links again and again and records every change.
    When
    For links that go up and down now and then.
    How long
    As long as you choose (default 10 min).
    Safe?
    Yes - it only reads.

    For links that come and go: both ends are read again every few seconds and every change is recorded (link up / down, admin, IFCP, error and FEC counters). Read-only.

    Stop ends it early; the report covers the rounds read.

    Cabling plan check

    What is this?
    What
    Compares how the rack SHOULD be cabled (a list from the site) with what the check found.
    When
    After re-cabling, or when links reach the wrong GPU.
    How long
    Instant (uses the latest check).
    Safe?
    Yes - nothing is logged into.

    The expected cabling against what the latest scan of this rack found (no login): ports missing, wrong descriptions, links that reach a different GPU port than planned (with the move to make), links not in the plan.

    Link scan

    What is this?
    What
    Checks every link of the rack and names one root cause per problem.
    When
    First thing on a rack, and after any change.
    How long
    1-3 minutes on a mini rack, longer on a full rack.
    Safe?
    Yes - it only reads.

    Every GPU link (switch port to GPU port), one root cause per problem link, GPU state. Read-only.

    Broadcom shell view

    What is this?
    What
    Reads, from the switch chip itself, whether light / signal arrives on each lane of a port and how good it is.
    When
    When a link has no physical link and you need to know which side is at fault.
    How long
    About 20 seconds.
    Safe?
    Yes - read-only lookups.

    Lane-by-lane signal, receiver lock, link training and signal quality from the switch ASIC (bcmcmd lookups, read-only).

    Repeated ping map

    What is this?
    What
    Sends test packets around all GPUs several times and maps the failures to ports and switch chips.
    When
    For loss that comes and goes.
    How long
    Rounds x wait (default about 3 minutes).
    Safe?
    Sends test packets; changes nothing.

    A ring of L2 pings, repeated; failures mapped to GPU port numbers and switch ASICs, sticky (every round) or moving.

    Isolate one link - takes it DOWN

    What is this?
    What
    Takes one end of one link DOWN for a few seconds and brings it back, to see which end a fault follows.
    When
    Only when asked to, with the people using the rack informed.
    How long
    About a minute.
    Safe?
    NO - it interrupts that link. Guarded: GPU links only, avoid-list honoured, always brought back.

    Takes ONE end of ONE GPU link down for a short hold and brings it back, to see which end a fault follows. Only ports described as cabled to a compute tray; never a port in the inventory's avoid list; the end is always brought back (also on Stop); afterwards every port of that switch ASIC that was up before must be up again. Traffic over this link is interrupted - make sure nobody is running on it.

    SSH access

    What is this?
    What
    Checks that this machine can log in to every tray of the rack (needed for every check). Where it cannot, type that tray's password once and the key is installed.
    When
    Once per rack, before the first check - and when a check says 'login refused'.
    How long
    A few seconds per tray.
    Safe?
    Adds this machine's key to the tray (like ssh-copy-id); nothing else.

    The tools log in with an SSH key and need sudo without a password prompt. Check each node; where the key is missing, type that node's password once and install the key (like ssh-copy-id). The password is used for that one login and not kept.

    Glossary
    
  
    
    
    Switch tray (st1, st6)
    The network switch of the rack. Each has 2 switch chips (ASICs: asic0, asic1) with many ports (Ethernet1, Ethernet257, ...).
    
    
    Compute tray (c1, ct13)
    A server with 4 GPUs. Its position in the rack is its slot number.
    
    
    GPU port
    Each GPU has 36 network ports (0-35); each is cabled to one switch port. That pair is a link.
    
    
    BDF (0002:01:00.1)
    The address of a GPU inside its tray. A tray's 4 GPUs are 0001, 0002, 0003, 0004.
    
    
    Topology
    How every GPU port is cabled to a switch port - see the Topology tab (full rack: 18 trays x 4 GPUs x 36 ports, 6 switch trays).
    
    
    Plane
    All links that use the same GPU port number form one plane. Losing a link reduces the planes a group of GPUs can use.
    
    
    AFM
    The fabric manager software: it programs the switches and GPUs. Its view (optional) needs its admin password.
    
    
    vPOD
    A group of GPUs that work together; AFM programs the links of the GPUs in it.
    
    
    IFCP
    The control protocol each GPU port runs with the switch once the cable is up. No IFCP session = the link carries no traffic.
    
    
    FEC
    Error correction on the link. Corrected errors are normal; uncorrected ones are a problem.
    
    
    Broadcom view / lanes
    Reading the switch chip directly: whether signal (light) arrives on each lane of a port, and its quality (SNR).
    
    
    Node agent
    The AFM software on the switch tray that manages one compute tray's GPUs.
    
    
    degraded / down
    Down: the link does not work. Degraded: it works but something is wrong (errors, not programmed, no IFCP...).
